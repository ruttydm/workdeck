# Repository issue forms

Two complete Hunk baseline blobs are reproduced by native Rust tooling:

| Source | Blob | Covered bytes | Destination |
| --- | --- | --- | --- |
| `.github/ISSUE_TEMPLATE/bug.yml` | `1a23f41ba03ba9e8c3c75b5a5ecdae897401be89` | `[0,1152)` | same Workdeck path |
| `.github/ISSUE_TEMPLATE/contribution.yml` | `7b96da37888c55c57da671cc1b3a802fa1e53eb2` | `[0,978)` | same Workdeck path |

`cargo xtask repository-forms generate` reads each entire source through
`git show 2c00f4358b89cfc0a6b04459ffc538ba601aa3c2:<path>`; there is no committed
source mirror. It adds MIT attribution comments and makes these substitutions:

- The contributor-guide link names `ruttydm/workdeck` instead of `modem-dev/hunk`.
- Expected-behavior copy names Workdeck.
- Version guidance requests `workdeck --version` and the installation method,
  replacing the upstream executable/npm-package alternative.

All other bytes are retained, including titles, labels, descriptions, markdown,
field types, IDs, order, and required/optional settings. YAML parsing validates
the result. `check` compares every generated byte and requires a real contributor
guide; it never repairs files. Both `cargo xtask verify` and strict pinned-source
`cargo xtask port audit` run that check. Symlinked form paths are rejected.
The native tests check transformation fidelity, field requirements, malformed
YAML, empty forms, and missing/duplicated source links.

`CONTRIBUTING.md` adapts the upstream guide to existing native build, extension,
test, media and release-fragment workflows. Its broader source interval remains
unmapped pending its own full verification. The source contact configuration
also remains unmapped: Hunk's Discord is not represented as Workdeck support.
No remote labels, settings, issues, discussions, or GitHub state were changed.
